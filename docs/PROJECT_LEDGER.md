# Журнал проєкту Aolithium Live

Новіші записи — зверху. Повна історія проблем і рішень (з неї буде урок з програмування).

## 2026-10-16 — v0.1.0: перша версія (чат «Aolithium-battary»)

**Звідки взялось.** 16.10 20:08 faric у чаті «GitHub Storage»: батарею Aolithium зняли з виробництва, застосунок прибрали
з Google Play — «щоб Aolithium жив далі». Того ж вечора Aolithium 1.3 збережено з M30s (`com.ao.lithium`, 5 частин APK)
і поставлено на бабусин Redmi через SAI. faric записав відео застосунку, підключеного до батареї.

**Розбір (без розбору APK).** Адреса батареї починається з `A4:C1:37`; aiobmsble за цим початком впізнає плату **JBD**;
BMS_BLE-HA прямо називає «Aolithium batteries» серед батарей з JBD; усі поля Aolithium збігаються з відповіддю JBD 0x03.
Висновок: Aolithium — перефарбований стандартний застосунок для JBD, протокол відкритий. Деталі — `docs/PROTOCOL_JBD.md`.

**Рішення faric (20:40, кнопками).** Назва — Aolithium Live; тест на A26, M30s і Huawei Mate 10 Lite (Android 8) → мін. API 26;
обидві плати (JBD зараз, JK BMS — у мами); репо публічне. Репо створено ~20:45; доступ Claude — ~20:50, після того як
брат підтвердив співпрацю (різні акаунти; поки чекали, faric сказав «збирай аналіз у себе, потім запушиш»).

**Що зроблено.**
- Ядро без Android (`core/`): команди читання й сума JBD; збирач кадрів зі шматків по 20 байт (зіпсоване відкидає,
  після загубленого шматка відновлюється); розбір 0x03/0x04/0x05/0xAA; знімок стану (потужність, напрям струму,
  час до порожньої/повної, різниця комірок з оцінкою); захисти людською мовою; числа українською (кома, «А·год»).
- Bluetooth (`ble/`): пошук 15 с з впізнаванням JBD/JK; зв'язок в одному своєму потоці (Android не любить паралельних
  операцій GATT); обидва колбеки сповіщень (Android 13+ і старші); до 3 повторних підключень; журнал зв'язку.
- Екрани: «Батареї» (доступи → мої → пошук), «Батарея» (циферблат заряду, стан плати, захисти, зараз, комірки стовпчиками,
  плата, лічильники, дії), «Довідка» з демо. Книжкова й альбомна. Поворот не рве зв'язок (`LinkHolder`, 5 с запасу);
  сховав застосунок — через 5 с батарея вільна для Aolithium.
- Стиль, вікна, значки, меню, CI — з Track Catcher; свій акцент (блакитний) і **свій ключ підпису** (`AL_*`).

**Перевірено кодом (у Claude, без телефона).**
- 39 юніт-тестів ядра (Kotlin-компілятор і JUnit з Gradle в `/opt` — `tools/dev/run_core_tests.sh`).
- Повна компіляція застосунку проти android.jar API 36 (`tools/dev/compile_android.sh`) — справжня перевірка все одно CI.
- Аудити інтерфейсу (UI-01…10) і публічного репо (+ правило: справжня адреса батареї faric у репо заборонена).

**Проблеми по дорозі (для уроку).**
1. *Приклад кадру з документації не сходився.* Кадр Chins у `docs/jbd_bms.md` aiobmsble має довжину 0x22 (34), а даних
   лише 32 байти — сума не сходиться; тест упав. Висновок: документацію-приклад не брати як справжній запис; кадр зібрано
   своїм `Jbd.responseFrame` з тих самих даних + 7 байт. Справжні кадри — лише з тестів aiobmsble.
2. *Ім'я змінної збіглось з полем Android.* У `BatteryScreen` колонки звались `left`/`right`; усередині
   `LinearLayout.apply { addView(left, …) }` Kotlin узяв `left` самого LinearLayout (число — координата), а не колонку.
   Компілятор зловив («none of the candidates is applicable»). Виправлено: `leftCol`/`rightCol`. Урок: у `apply {}`
   не називати змінні як поля View (`left`, `right`, `top`, `bottom`, `width`, `id`…).
3. *Перенесення зі «шаблону» небезпечне.* Скрипти меню скопійовано з Track Catcher автозаміною — і шлях ключа лишився
   `~/.android/track-catcher.jks`: пункт 7 узяв би ключ Track Catcher. Помічено при перегляді, виправлено; додано
   контракт-тест `OwnKey` (у меню, CI й Gradle не має бути `track-catcher`, `TC_`).

4. *Подвійне коло читання.* Перша версія `startReading()` перевіряла лише «чи чекаємо відповідь». Між колами (2 с паузи)
   ця перевірка пропускала б повторний старт — і йшли б два кола паралельно. Помічено на перегляді коду до телефона;
   тепер прапорець `reading` на все підключення. Плюс запасний старт через 1,5 с, якщо Android не повідомив «сповіщення ввімкнено».
